# Voice Agent

Select **Voice Agent** below **ToolUse**. Choose **Whisper Medium** (default) or **Whisper Large V3 Turbo**, and **Gemma 4 E2B** (default) or **Gemma 4 E4B**. Choose each model's backend separately. The **MTP** switch defaults to **on for E2B** and **off for E4B**; each model remembers its selection while the settings screen remains open. Unsupported model/backend combinations disable MTP. Then press **開始** and grant microphone access. Speech offers available ailia environments plus a converted QNN model on supported SoCs; Gemma offers CPU / supported QNN; synthesis offers available ailia environments (QNN requires FP16 support). Backend choices follow the selected model's device support; selecting E4B on a device without its QNN model falls back to CPU.

The setup screen lists two tools: `set_air_conditioner_temperature` (for example, **エアコンを20度にして**) and `take_photo` (**写真を撮影してください**). Gemma calls them using the SDK's structured tool-call API, receives their results, and then produces the spoken answer. Tool syntax is not shown or read aloud. As in the ToolUse sample, temperature changes update sample state rather than a physical appliance; the current setting appears at the top left after a successful call. The setup screen lets you choose **アウトカメラ** (rear, default) or **インカメラ** (front). Photography uses the selected camera, asks for camera permission only when requested, and shows the latest still image in a small thumbnail at the top right. Both displays start hidden and reset when the session ends. Photos are temporary app-cache files and are deleted when replaced or when the session ends. A matching Gemma image encoder is downloaded for the selected model/backend. Captured photos are added to the structured conversation history as bounded, upright JPEG image data, so Gemma can describe them and answer follow-up questions even after the preview is replaced. Images leave history together with their original conversation turn.

During recognition, Whisper intermediate callbacks update the input text in place. During Gemma generation, safe text deltas update the response in place; tool-call and control markers are withheld, including markers split across tokens. Final structured responses remain authoritative for conversation history. Speech synthesis also consumes the filtered generation previews, then flushes each round's remaining text from the parsed response without repeating phrases already queued. These previews keep the existing non-LIVE Silero/Buffered/finalize/transcribe/reset protocol, so recognition previews start during decoding after the utterance is submitted, rather than while the microphone is still recording. Cancelling discards late UI previews while retaining the recognized request and the reply generated up to the interruption in the internal conversation history. Incomplete tool syntax is never saved; parsed tool calls without a completed result receive an interruption error so the next prompt has a valid history.

A system prompt guides tool use and concise Japanese voice replies. The recognized request is initially submitted unchanged; structured assistant tool calls, matching tool results and captured images are passed with `setPromptJson`. When history approaches the context window, it is reduced to approximately its newest one eighth by token count, with a small minimum for message overhead and enough text to continue. A brief prefix of the active user request is retained alongside the recent answer tail to keep the continuation on task. Parsed tool calls and their results stay together; one newest tool exchange or image may round up the target if it still fits. Oversized text keeps its recent tail. Near a window boundary, generation prefers a sentence ending or newline; continuation-only instructions ask Gemma to finish any interrupted text without restarting. If generation reaches the window boundary (including native `CONTEXT_FULL`), the generated assistant text is saved, history is compacted, and a hidden **続けてください** request resumes generation. The visible response and punctuation-based speech stream continue cumulatively without resetting the session, input text, or thinking status. Only the retained suffix enters later prompts; the full response remains visible and is spoken once. A model that repeatedly rejects the minimal history without producing text still reports an error.

**応答の音声合成** is enabled by default. Turn it off to display responses as text and immediately return to listening without synthesizing or playing the answer. In microphone mode this also skips downloading the voice model. In test mode GPT-SoVITS still synthesizes and plays the input queries; only response speech is disabled, so its backend remains selectable. Add `-e voiceAgentSpeechOutput false` to the instrumentation command below to exercise two text-only responses.

For a repeatable test, select **テスト：GPT-SoVITS合成音声** and enter one query per line. The defaults request a self-introduction and ask what one plus one is. The selected GPT-SoVITS backend synthesizes and plays each query, pushes its PCM into the same ailia Speech/Silero buffered input used by microphone capture, then finalizes and transcribes the detected utterance and runs the normal Gemma response and GPT-SoVITS playback path. Before each query, the test feeds a 400 ms playback tail (from the previous answer when available) followed by 1.2 seconds of silence and checks that neither starts a turn. The actual question must then make the SDK report Buffered after its trailing silence. Query text is never passed directly to Gemma. Microphone access is not requested or used by this UI test mode. Each query runs once in order; after the final answer the orb continues its gentle idle motion and the last recognized query and answer remain visible until **×** is pressed. Cancelling a test switches to microphone mode and requests microphone permission if needed. All three backend selections still apply.

After installing the app and Android test APKs on a supported device with the QNN models cached, run the same two synthesized queries through the public session API:

```shell
adb shell am instrument -w -e class jp.axinc.ailia_kotlin.VoiceAgentInstrumentedTest#synthesizedQueriesCompleteTwoVoiceTurns -e voiceAgentNative true ai.ailia.ailia_kotlin.test/androidx.test.runner.AndroidJUnitRunner
```

The instrumentation test checks both questions through VAD, recognition, responses and stage transitions. After the second answer it explicitly grants microphone access and resumes real microphone capture, checking for more than two seconds that playback does not cause an unsolicited turn. It saves queries, recognized text, answers, states and the microphone observation to `voice-agent-synthesized-test.json` in the app's external files directory. Run it in a quiet room without speaking during the final microphone observation.

The first start downloads the selected models and dictionaries into the shared model directory. The CPU Whisper encoder alone has approximately 2.5 GB of external weights; allow sufficient storage and memory. When MTP is enabled, Gemma downloads and opens its matching MTP Assistant on supported model/backend combinations (three draft tokens per step), before opening the multimodal projector for photo input. With MTP disabled, the Assistant is neither downloaded nor opened and Gemma uses ordinary decoding. Legacy QNN formats without a matching Assistant use ordinary decoding. MTP initialization errors are reported rather than silently disabling MTP. Whisper and its Silero VAD are initialized for each listening turn. After recognition completes, the speech engine is reset and released before Gemma loads on the model worker. Response synthesis creates a private GPT-SoVITS instance on a dedicated synthesis worker, so Gemma and GPT-SoVITS can be resident together during generation. Microphone PCM can queue while the speech engine loads; model loading adds latency to each turn.

`AiliaVoiceAgentSample` coordinates session state and microphone turns. `VoiceAgentModels` owns model downloads, inference and structured conversation history on the model worker; `VoiceAgentTools` defines the tools and sample state. `VoiceAgentCamera` starts a private metering stream, waits for exposure and white balance to settle, then captures a still photo in quality mode without showing a preview. The wait is bounded for devices that do not report convergence. It releases both camera use cases on completion or cancellation. `VoiceAgentPlayer` owns audio output and playback waveform sampling. `VoiceAgentSpeechQueue` connects streamed text to a dedicated synthesis worker and a separate playback thread. Both workers are joined before the next recognition turn or model cleanup.

While Gemma is generating, filtered text is split incrementally at Japanese/English punctuation and line breaks, preserving closing quotes and decimal numbers even across generation batches. A boundary waits for the next character to include trailing quotes or distinguish decimal punctuation; the final unterminated phrase is flushed at the end of each tool/answer round. GPT-SoVITS starts loading on its own worker as generation begins, then synthesizes arriving phrases in order with a single model initialization and `SetReference` call per response; subsequent phrases only convert their own text and synthesize with that reference. The LLM queues text without waiting for synthesis or playback. The status stays **考え中** during generation, switches to **音声合成中** when generation finishes, and becomes **発話中** when playback starts. Playback is held until generation completes; it then drains the prepared clips while synthesis continues, with at most two completed clips waiting in the PCM queue. If synthesis is slower than playback, there can be a pause between phrases. Interrupting discards pending clips and stops current playback; an in-progress native synthesis call finishes before the next recognition runs. If generation fails or is interrupted, pending speech is discarded and both speech workers are joined before the next turn. The response text remains the full answer, and waveform animation follows the clip actually playing.

During a call the settings, menu and chat history are hidden. An abstract, soft white orb appears against a black background. The same PCM-driven animation follows microphone input and the actual playback position, expanding and wobbling with audio amplitude. Gentle pulsing and movement continue at rest; model loading and synthesis have a subtle waiting motion until playback audio becomes available. Only the latest recognized utterance and assistant response are shown. The transcript scrolls to the bottom as the generated response grows. The sample uses Japanese recognition and a bundled Japanese reference voice. It detects the end of a turn after about one second of silence (maximum 30 seconds per recording), keeps a short conversation context internally, pauses the microphone during processing/playback, and automatically listens again after playback. Empty recognition results return to listening without invoking Gemma. Use **×** or Android Back to end the session. Leaving the foreground also stops capture and playback; model destruction is queued after inference on the same model thread.

After playback ends or is cancelled, input is excluded until 400 ms after the output stops. All remaining PCM, including quiet speech, is passed to ailia Speech with Silero VAD v6.2 (`silero_vad_v6_2.onnx`), using probability threshold 0.5, speech-start duration 0.25 seconds and speech-end silence 1.0 second. There is no RMS speech gate; RMS is used only for animation. Microphone capture itself resumes immediately, and the send button becomes available once samples beyond the settling window arrive.

The speech engine uses non-LIVE mode: push chunks until the first `Buffered`, stop microphone capture, call `finalizeInputData`, transcribe while buffered, verify `Complete`, and call `resetTranscribeState` before any subsequent input. `Buffered` can also be raised by the SDK after 30 seconds of audio; an empty result simply resumes listening. Manual send finalizes the same stream immediately. Every native operation, including pushes and cleanup after cancellation, stays on the model worker. The lifecycle follows the [ailia Speech agent input guidance](https://docs.ailia.ai/speech/).

The center button submits microphone audio without waiting for the silence endpoint, including short/quiet recordings. During recognition, LLM generation, synthesis or playback it becomes a cancel button. Cancelling stops and flushes playback, retains generated assistant text and completed tool results in history, discards later UI updates, and immediately resumes microphone capture. A turn cancelled before any assistant text or complete tool call is generated is rolled back. The blocking native synthesis API has no abort method: its current call finishes on its synthesis worker, which is joined before the next recognition can execute, while the microphone can already capture the next query. Models are still created and released on their owning worker. **×** at the bottom right ends the entire session.
